## Step 5 — Threshold mode

- [x] 10-bucket sliding-window ring buffer per group (~40 bytes). Landed 2026-05-19 in `event_pipeline/grouper.rs` as `ThresholdWindow` — `[u32; 10]` counts + `head_epoch`/`head_idx` + `bucket_width_ns`. Lazily allocated (`Option<ThresholdWindow>` on `Group`) so per-event groups pay zero. Bucket width = `window_s * 1e9 / 10` ns floored to ≥ 1, so sub-10s windows (down to `window_s=1`) still work. Buckets age lazily on observe/sum via `advance_to(now_ns)` zeroing skipped slots.
- [x] Promote PENDING → FIRING only when `count` reached within `window_s`. Wired in `grouper.tick` — threshold-mode groups gate firing on `window.sum(now) >= count` instead of `group_wait_s`; `group_wait_s` is now ignored in threshold mode (deliberately, per docs/event-pipeline.md "PENDING → FIRING (threshold: until count reached)"). Plumbed from `alert_engine::compile_one` so existing rules with `threshold_count`/`threshold_window_s` set in the DB now actually use threshold mode. Once firing, all the existing refire/heartbeat/resolve timers behave as in per-event mode. 6 new grouper tests cover: count reached fires, below count doesn't, ageing-out old events doesn't fire, cross-bucket spread still fires, refire+resolve still work, sub-10s window doesn't collapse to bucket_width=0.

## Cross-cutting follow-ups noted during step 1

- [x] **Aggregate response uses raw int for `action` (and likely `direction`).** Fixed 2026-05-17. Added `GroupBy::label_key` and applied it inside `EventStore::aggregate`, so both REST and GraphQL aggregate paths now return `"drop"`/`"log"` for action and dotted-IP strings for `src_ip`/`dst_ip` (instead of `"1"`/`"2"` and uppercase hex). `direction` isn't a current `GroupBy` variant — revisit if it's added. Tests in `event_pipeline::store` cover the conversions and the unknown-value passthrough.
- [x] **Agent re-enrollment changes node_id.** Investigated 2026-05-21 — **works as designed**, not a bug. The agent's `node_id = sha256(SubjectPublicKeyInfo)` is derived from `identity.key`, which is created with `OpenOptions::create_new(true)` (`fleet/agent/src/identity/file.rs:109`) and has no code path that deletes or regenerates it. The observed `a71527… → 5d537473…` change is the documented re-enroll flow triggered by the pre-1.0 "wipe controller DB on big feature changes" workflow: DB wipe → agent reconnects → controller `get_node()` returns `None` → `Disconnect` with reason *"Unknown node … re-enroll required (delete identity.key and controller-client.*)"* (`fleet/controller/src/grpc/management.rs:319-323`) → operator follows the instruction → new keypair → new node_id. Historical event fragmentation is the unavoidable consequence; we deliberately *don't* let a new key claim an old node_id because that would break the self-authenticating identity model. If event continuity across DB wipes ever matters, the fix is either backup/restore of `controller.db` or a CA-signed-cert rehydrate path (which needs the CA key to live outside the wiped DB first).
- [x] **TenantScope rollout.** Threaded `principal.tenant_slug` through the GraphQL surface (rules, audit, sessions, api tokens, enrollment tokens, pending generations, node/interface listings) and added a `ensure_node_in_tenant` guard at the top of every node-targeted mutation so a tenant-A operator cannot mutate a tenant-B `node_id`. `ControllerStore` methods that fan out fleet-wide (`list_audit`, `list_nodes`, `list_all_node_interfaces`, `list_enrollment_tokens`, `ApiTokenStore::list/revoke`) now take an explicit `tenant_id`. Background sweepers (token reaper, retention, watchdog) still pass `tenant_id: None` to the audit writer, which resolves to the node row's tenant when a `node_id` is present and falls back to `default` otherwise — see the next bullet.
- [ ] **Auth → tenant resolution.** Today everything is `default`. When real auth lands, resolve `X-Tenant` header (or `?tenant=`) to a `TenantScope` per request in middleware; reject mismatched API keys.
- [ ] **Clock skew.** Spec note: `ts_ns` is the agent's clock. Watch for skew complaints; cheap fix is to add `received_at_ns` on insert.
- [ ] **`events.node_id` as TEXT, not FK.** Intentional (hot path). If we want join-time integrity later, add a partial index rather than a constraint.
- [ ] **Persister overflow path.** Currently drops *individual events* when the in-memory buffer hits `max_buffered`. Verify under load that the broadcast channel doesn't also lag (separate `Lagged(n)` counter exists). Consider whether to size the broadcast channel and `max_buffered` together.
- [ ] **Codegen workflow.** With the SDL exporter in place, decide whether `npm run codegen` should default to the local `web/schema.graphql` or to `GRAPHQL_SCHEMA_URL`. Document it in the web README.
